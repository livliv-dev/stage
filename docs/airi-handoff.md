## 代码里已经有的

Stage 作为角色端，AIRI 作为对话端。完成回复用角色已有的声音说出，口型走现有播放路径。同一角色的会话绑定是 `livliv-stage:<角色 ID>`，轮次在 `livlivTurn`。连接和换角色时发送 `context:update`（`replace-self`，lane `livliv-stage:character`）。长回复按 Stage 已有分句（`。！？!?` 和换行）逐句准备。`spark:command` 里能认出的表情、动作、暂停和继续会做，并回 `spark:emit`。模块只宣布一次。Stage 不把自己注册成 `input:text` 的消费者。

## 实测和推断要分开

| 结论 | 依据 |
| --- | --- |
| 握手、绑定字段会原样传到消费者、`livlivTurn` 与 `contextUpdates` 会透传、无令牌时可能多一次 announce | 对照 AIRI `473112a` 源码，并用真实 `@proj-airi/server-runtime@0.15.4` 做了路由探针。探针里的对话模块是夹具，不是 AIRI 应用，也没有模型。 |
| 完成事件的 `message.content` 不含 `<|ACT>` | 夹具探针看到解析器把标记从将要发送的 content 里拿掉。这不能当成「线上没有标记原文」。 |

## 可复现的成功前提

2026-11-17，在本机用浏览器开发页做过一次 real-model 端到端，没有用桌面版，也没有用真实声卡。

- Stage 为当时的 PR 头（逐句播放那次提交）。角色用模板「AI 主播」，人设和说话风格是填好的。
- AIRI 为 stage-web，基线是 `473112a` 的 server-runtime 0.15.4。另有一处 **不在本 PR** 的 `input:text:voice` 上游修复；它不改变 `input:text`，也**没有**修下面的冷启动注册。两件事不要写成同一个已修复项。
- AIRI 自己的语音关掉。Stage 的语音接口指到本机 Piper 兼容合成（离线，无密钥），所以口型跟的是合成出的音频，不是系统语音的音节估算。
- 模型是 AIRI 里配置的真实对话模型，只跑了短对话。

在**手动补过一次** AIRI 的 `chat-ingestion` 消费者注册之后：

- 7 轮都是 Stage 把 AIRI 的完成回复说出来，合成请求有真实音频，口型数值从安静抬到接近全开。
- 绑定保持为同一个 `livliv-stage:<角色 ID>`。从第 2 轮起，发往模型的请求里带有此前的历史。Stage 断开再连、`livlivTurn` 回到 1 之后，仍是同一条 AIRI 会话。
- 中文长回复按 `。！？` 和换行逐句合成。Stage 侧打断时，被打断的那句立刻停，后面还没开始的句子不再合成。

这些都依赖上面的手动注册。没有那一步时，runtime 日志是没有 `input:text` 消费者，AIRI 不回应。

## AIRI 冷启动注册（上游，未修）

stage-web 冷启动后可能不注册 `chat-ingestion` 消费者。`module:authenticated` 就已经把连接当成完成，随后的 `module:consumer:register` 在模块宣布完成之前发出，发送被丢掉。重连回调里才会再注册。同一段逻辑在 tamagotchi 里也有，桌面版没有测。

这和「`input:text:voice` 没有处理器」不是同一个缺陷。后者不在本 PR。

临时办法：AIRI 起来之后，把 server 断开再连一次，或重启 server-runtime，让 AIRI 走重连并补注册。Stage 已连接但说话没有回应时，先查这个。本分支没有自动重试或代注册。

## 观察，但没有当成已完成

- 角色资料以上下文附在用户消息后面送到模型。AIRI 的系统提示仍是它自己的角色卡（实测里名字仍是 Iru）。前一两轮回答不一定采用 Stage 上的名字和人设，后面几轮才更接近。模型答过的自我介绍不要当成 AIRI 或 Stage 的产品身份。
- 记忆绑定在机制上续上了同一会话，但当次模型对先前事实的复述并不稳定。
- 打断只保证 Stage 停播。AIRI 仍把被打断的那一整段记成已经说过。
- 英文句号后的长回复被整段合成，第一声要等整段结束。Stage 现有分句本来就不把 ASCII `.` 当句号。
- 关掉 AIRI 语音后没有第二路合成。AIRI 窗口仍显示它自己的形象。没有找到已验证的「隐藏模型」开关。只采集 Stage 窗口是采集建议，不是已验证的隐藏选项。
- 浏览器控制台里有开发模式 StrictMode 的 WebSocket 早关，以及与本集成无关的 `/api` 502。

## 请团队接着做的 7 项

不要把下面任何一条写成这支 PR 已经完成。本地读过 `categorization.speech` 的试验已还原，不在分支里。

1. **读真实原文。** `readRaw` 应先读 `data.message.categorization.speech`，再兜底 `generationTranscript` 里各 round 的文本。用真实完成事件的形状做单测：content 是干净句子，speech 里有 `<|ACT …|>`，解析后的表情不是中性。验收：真实一轮回复里，标记中的表情出现在对应句子上。
2. **情绪延续。** AIRI 的约定是标记一直生效，直到下一个 `<|ACT>`。现在按标记所在位置切句，后一句若没有新标记会回到中性。验收：一句 happy、下一句无标记，第二句仍是 happy；遇到新标记才换。
3. **英文分句。** `.` 后接空格或换行要切开，并排除小数和常见缩写。不要改坏现有的 `。！？!?`。验收：一段多句英文会逐句合成，第一声不必等整段；`3.14` 和 `Mr.` 不被切开。
4. **角色身份。** 现在的上下文是资料块，压不过 AIRI 卡里的「你的名字是 …」。文案要明确：此刻以 Stage 上这个角色说话，名字和人设以这份资料为准。文档里建议用户在 AIRI 换成对应角色卡。验收：系统提示或等效指令能让回答使用 Stage 角色名，而不是只在用户消息末尾附一段资料。
5. **打断回执。** 停播时用 `context:update` 或 `spark:emit` 告诉 AIRI 实际说到哪一句。验收：只听到第一句时，AIRI 后续历史里不再把后面几句当成已经说完。
6. **冷启动。** 在用户文档写明上一节的临时办法，并标成依赖 AIRI 上游修复，而不是 Stage 已修好。验收：按文档操作后，新开的 AIRI 能收到 Stage 的 `input:text`；文档不把 `input:text:voice` 的修复写成这件事的修复。
7. **入门引导。** AIRI 已接管对话时，不要再提示去接 Stage 自己的模型和声音。验收：打开 AIRI 主持并连上之后，相关引导不再把用户送回 Stage 模型设置。

`spark:command` 保持现有单测即可，不要写成真实模型已经走到。

## 建议的验收顺序

先做第 1、2 项，用一条带 `<|ACT>` 的真实完成事件就能同时看字段和跨句。然后做英文分句和打断回执。角色身份和第 6、7 项可以并行。全部完成前保持默认关闭，不要据此打版本或发布。

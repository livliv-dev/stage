# AI 聊天、记忆、反应与游戏互动

## 使用

- 开始页有四个目标：我来演（可以加一个 AI 搭档）、AI 来开播、和角色聊天、做一段视频。选一个就摆好舞台（舞台上已有自己的角色时沿用它们），并打开这个目标的「准备清单」：只列它需要的项，每项有状态、「测试」和去设置的入口，设好后回到清单。开始页可以从舞台名旁的菜单再打开，原来的模板在它下面一行。
- 控制台只有一个开始按钮，按目标命名：开播、开始聊天、开录；我来演没有开始按钮（用「输出到 OBS」），加了 AI 搭档时是开播。按钮旁三行选项：谁上场（每个角色是我来演、AI 来演还是只展示）、谁在看（只有我 / 直播间，直播间可以接 Twitch 弹幕，也可以不接）、你参与吗（不参与 / 打字 / 按住说 / 免按键 / 我也上镜）。现在跑不了的组合显示为不可选，并写明原因。时长和句数上限、Twitch 都只在这里设；语言、聊天方式、谁先说、抢话、节奏和直播间没有弹幕时做什么折叠在「更多」里。没有会话时，空格键做开始按钮做的事；会对外（直播间）或录制的开始只打开准备清单，用 LivLiv 积分的台词只从按钮开始。
- 选「日常陪聊」或「深入讨论」，以及主动接话：没有回应时最多主动接话一次，然后等待。
- 「免按键」沿用已有语音识别、文本模型和角色音色。开启后直接说话，停顿后自动发送；按住说话仍可使用，并会接管自动模式。自动语音与「实时通话」分别使用现有 ASR/TTS 和原生 Realtime 声路。
- 「对话记录」可以恢复同一角色组合、同一公开范围的会话，或者开始新对话。停止不清记录；清空会清除当前会话台词。
- 输入「记住：……」或在台词旁选择「记住」，保存明确希望保留的事实。记忆面板可新增、编辑、删除、查看来源和设置是否可在直播使用。
- 私聊和公开记忆各自保存会话，公开的会话读不到私聊的记忆。范围在控制台状态行的小标签里选（「私聊」或「公开记忆」），标签显示这次开始实际会用的范围：选了直播间或做一段视频时就是「公开记忆」。OBS 输出窗口、录制、好友联播或直播间（Twitch、开播中）任意一个开着时，会话一律公开：不读也不写私聊记忆，对话记进公开记录，标签固定为「公开记忆」；私聊进行中打开其中任何一个，会从下一句起转成公开。全部关掉后才能再选私聊。默认项目导出不含聊天和记忆，导入项目会建立新的本地档案关联。
- 修改参与的 AI 角色组合时停止当前会话并打开对应记录；切换同一组角色的镜头不停止会话。复制角色建立新的档案。
- 角色设置中的「AI 反应」控制强度、真实模型表情映射、保持时间和间隔；人工表情保持优先，自动反应不覆盖面捕或朋友的角色。

## 界面与音色选择

- 控制台可直接打开「记忆」；同一面板内切换对话记录和记忆，不再叠两张卡片。添加记忆时才展开输入框。
- 控制台的状态行是一排小标签：模型、声音、直播间、引擎（AIRI，或标准并写明原因）、公开记忆 / 私聊、准备清单；点标签直接去对应的设置。进行中时控制台是输入框、按住说话、跳过这句、暂停和结束。
- 「设置 → 连接」集中放所有服务商和密钥：文字模型、声音与语音识别（服务商支持时默认「一个密钥用于全部」）、实时通话（折叠）。每项都能测试，设置可以搜索。
- 自动反应提供轻微、自然、活泼三个入口，可直接预览；表情对应和节奏放在展开设置中。
- LivLiv 角色声音显示当前音色，点开可按名称和描述搜索，使用接口提供的分类筛选，或查看最近使用。接口没有分类时保留搜索，不推测音色属性。
- 选择和试听候选音色不会修改当前声音，只有「应用音色」才会保存。试听沿用 LivLiv 角色语音生成接口，界面明确说明用量计费；关闭面板或开始聊天会取消试听。
- 游戏互动默认折叠，端口设置按需展开；开启后显示连接状态和可复制的地址。

## 模型服务的范围

LivLiv 官方 AI 保留既有积分对话与角色声音接口。客户端在原有 14 行上下文内，把最近更新的最多三条记忆、已有摘要及外部事件明确标为背景资料发送，每行最多 300 字；近期真实对话保留原归属。深入讨论使用官方接口已有的长回答选项，不能等同于自有模型的完整讨论提示。官方接口尚不返回自动摘要，也不提供 Neuro 的通用动作决策；这两项需要配置自己的模型接口。真实官网模型对这些背景资料的回应质量仍待联调。

## 数据与接口

`memory.ts` 保存会话和记忆，`chatHistory.ts` 负责当前会话身份与版本，`chatContext.ts` 组合近期轮次与前文摘要。摘要随正常模型回复生成，不单独请求模型。摘要质量取决于所选模型是否遵循输出约定。

删除或纠正记忆会使相关摘要失效，并排除源行及其旧 AI 派生内容；原始台词仍可在记录中查看和单独删除。跨窗口保存使用递增版本，删除会话后迟到保存不能恢复它。读取或保存失败会显示错误，不能把未保存宣称成已保存。

会话在 `stage/src/sessions/` 里运行。所有会话走同一个循环（`runner.ts`）：时长上限、等待、你的台词、说一轮、失败重试、轮与轮之间的停顿、各种上限和结束时的收尾，都在这里。策略（`policies/`：角色之间聊、和你聊、直播间）只说各自不同的地方：下一个谁说、回应什么、怎么算失败、上限和提示语。进来的东西排在一个收件箱队列里（`queue.ts`：打字、语音、弹幕、外部事件、游戏事件）。正在运行的会话是一个值（`run.ts`），由运行器交给策略和说话路径（`speak.ts`）。循环和策略不直接碰舞台，只通过一个环境接口（`env.ts` 是舞台上的实现），所以单元测试不用浏览器就能跑。四个引擎（`brains/engines/`：自己的模型、LivLiv、演示、AIRI）接收同一种请求；整句说还是逐句说，由引擎的能力决定。`conversation.ts` 只剩界面和测试调用的 `talk.*`。生成、声音准备、待播句段和播放的生命周期绑定在同一轮。已完成句段保留，被打断的句段不作为完整已说内容。和角色聊天与直播间中的模型生成和游戏动作决策共用当前会话的生成次数上限。LivLiv 声音一句只调用一次 `/say`（`test:say-once`）。

## 免按键语音

默认关闭，不保存为下次自动开启。开启时连接麦克风，并显示收音状态；暂停会释放麦克风，继续后重新连接。点击关闭、Esc、停止会话、关闭语音识别或麦克风静音都会结束自动收音。切换麦克风会取消旧输入并连接新设备。桌面窗口切到后台仍可收音。

本地能量检测先保存声音起始部分，约 160 毫秒持续声音后让角色让位，约 800 毫秒停顿后送出。短促噪声不调用识别，也不打断角色。识别与下一句收音并行，按顺序提交转录，待当前输入处理完再回应。已说的转录直接进入记录，不再重复朗读真人原话。角色说话时收到的简短附和会保存，但不另生成一轮回答。直播中的自动语音会主动让位，手动按键说话仍沿用原来的插话设置。

每段最多录 30 秒，识别队列最多 4 段；队列跟不上时明确提示并停止收音。服务错误显示在控制台，可继续说或手动关闭。输入使用已有麦克风混音音量及浏览器回声消除、降噪配置。真实麦克风、扬声器外放、背景音乐和不同设备上的效果仍待实体设备验收；界面提供耳机提示。

## 独立 Neuro 模块

`neuro/` 是独立 Node 包，不依赖 Stage、Electron、Player、模型配置或记忆。它管理 WebSocket 协议、动作目录、参数校验、关联结果和连接生命周期。`desktop/src/neuroHost.ts` 与 `stage/src/neuroBridge.ts` 负责适配；聊天核心只接收通用外部事件和动作决策请求。

桌面「设置 → 通用 → 游戏互动（Neuro 协议）」选择角色、端口并启用。本机接口默认关闭，不在重启后自动监听。启动前准备公开会话，界面显示实际连接地址。支持事件、注册动作、force、结果回传、游戏对白让位和整轮发言结束；游戏对白不阻止静默动作决策。

独立运行、测试与已支持的协议/JSON Schema 子集见 [Neuro README](../neuro/README.md)。协议兼容不提供 Neuro-sama 模型或其服务使用权限。语音音频侧通道和真实第三方游戏尚未验收。

## 与实时通话的衔接

可选的 WebRTC 实时/双工语音已接入百炼与 OpenAI，使用同一份档案、公开范围、摘要和记忆，配置与验证见 [实时通话说明](realtime-voice.md)。传输由独立声路处理，不在 Neuro 模块实现。普通识别/TTS 与 Realtime 都需要向会话层报告：用户开始发言、已经播放的内容、角色发声、整轮完成及中断。

本轮提供 `talk.hearing()`、`talk.onSpeech()` 及完整的轮次取消路径。`onSpeech` 的 `final:false` 表示句段/播放状态变化，整轮结束才发送 `final:true`，并保留 `cancelled`。Realtime 已接入同一份档案、公开范围、摘要和记忆；未播放的完整转录不会存为已说内容。录制和联播仍应经过 Actor/Player 的既有声路。

OpenAI Realtime 的 WebSocket 连接需由客户端停止本地播放、清待播音频并用实际播放时长截断服务端上下文；WebRTC 路径由服务端处理输出缓冲截断。原生语音不保证提供逐字截断后的准确文字。依据：[官方轮次与截断说明](https://developers.openai.com/api/docs/guides/realtime-conversations)、[VAD](https://developers.openai.com/api/docs/guides/realtime-vad)。百炼也提供 VAD 与语音打断，具体字段按所选模型核查：[官方 SDK 说明](https://help.aliyun.com/zh/model-studio/omni-realtime-java-sdk)。

## 验证与限制

在仓库根目录运行针对性浏览器检查：`npm --prefix stage run test:chat`、`npm --prefix stage run test:memory`、`npm --prefix stage run test:handsfree`、`npm --prefix stage run test:lifecycle`。单元测试沿用 `npm --prefix stage test`、`npm --prefix desktop test`，独立协议包使用 `npm --prefix neuro test`。

本轮浏览器使用模拟文本和语音服务；真实模型的讨论质量、语音延迟、扬声器回声与长期直播稳定性需单独验收。没有部署公网服务，也没有发布安装包。

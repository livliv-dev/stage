# Stage 项目文件

新的 `.livstage` 文件包含全部命名镜头、当前镜头、LivLiv / VRM / PNG 角色、图片和背景。模型原始清单、作者、许可与水印保持原样。保留 livliv.ai 角色和示例角色的关联，声音服务仍按当前账号权限使用。朋友的临时素材、账号会话、模型服务配置和密钥不入包。

镜头共享角色身份、设备、追踪配置、人设、声音与 AI 会话；各自保存位置、大小、显隐、镜像、阴影、颜色和内部取景。隐藏只影响画面，设备与 AI 由各自控制项决定。切镜头保留 Player 和画布，并先向输出窗口同步场景，再发送新姿势。

所有镜头共用舞台尺寸，修改尺寸会调整全部镜头。录制保持开始时的导出尺寸；之后的画面等比适配，比例改变时留边。

文件采用 UTF-8 ZIP，含 `project.json`、`models/` 和 `pictures/`。最终文件上限 512 MiB、8,192 个条目，单角色沿用 Player 的 256 MiB 上限。图片须能解码，不超过 64 MiB、单边 16,384 px 和 6,400 万像素；直接导入与项目导入采用同一检查。

读取时核对结束记录、中央目录、路径、压缩方法、实际尺寸和 CRC32。拒绝重复路径、加密、不完整文件及不支持的 ZIP64 / 多卷包。背景只接受完整的颜色或允许的渐变表达式，图片必须引用包内素材。ZIP 流使用 [fflate 公共接口](https://github.com/101arrowz/fflate)，目录与 CRC32 由 Stage 额外核对。

素材全部读完并通过检查后，在同一个 IndexedDB 事务提交角色与图片。此前的失败或取消不改变当前项目和角色库。导入使用新资源键，不覆盖已有模型；图片刷新后从持久 Blob 重建地址。撤销恢复整个镜头集合，离开的朋友也会从历史记录移除。

旧 `.livstage.json` 单场景文件仍可打开，保留原来的引用式存储方式；这台电脑没有的模型仍需重新导入。新的保存入口统一生成带素材的项目包。

检查命令：`npm --prefix stage run test:shots`、`npm --prefix stage run test:projects`、`npm --prefix desktop run test:stage-api`。项目流程包含全新存储分区、屏蔽原模型地址、刷新、独立输出、旧文件、取消、损坏包、导图时切镜、真实存储失败与实际 MP4 帧检查。
